# Structural Crime Scene Processing

## Exemplar Completed Forms

## Draft 1

---

## Purpose

This document shows what a disciplined, partially completed Structural Crime Scene Processing packet can look like in practice.

These are not "answer keys" in the usual sense.

They are exemplar outputs.

They model:

- lawful uncertainty
- anchor-first reasoning
- explicit residue
- refusal of premature narrative closure

The completed forms below are based on existing scenarios in the case exercise companion. They are intentionally bounded to the information present in those scenarios.

---

## How to Read These Exemplars

These examples should be used to teach three things:

1. what a strong first-pass packet looks like
2. how disciplined writing differs from polished storytelling
3. how unresolved questions remain visible rather than being hidden

If a reader finds the forms "undercommitted," the forms are probably doing their job.

They are not supposed to overclaim.

### Boundary status

**Informational boundary established:** Partial  
If yes, how: neighbors separated, but informal discussion already occurred before full scene-team arrival

**Authority boundary established:** Partial  
If yes, how: patrol present and controlling access, but scene command not fully transferred to investigative lead

**Interpretive boundary established:** No  
If yes, how: N/A

### Access and control

- Access log started: Yes
- Device / system access restricted: Partial
- Nonessential personnel removed: Partial

### Earliest perishable anchors to capture

3. Front entrance key-fob access events in same window

### Early contamination vectors

1. Neighbor cross-talk in hallway before full separation

### Likely explanation-density carriers already active

### Requested tests in order
